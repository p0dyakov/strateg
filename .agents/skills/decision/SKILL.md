# Решение

Основание: ADR, Microsoft Azure Well-Architected Framework, ссылка в README

1. Покажи рекомендацию, альтернативы, сильное возражение и оставшуюся неопределённость
2. Запроси явный выбор уполномоченного человека
3. До ответа оставь `approval: pending`
4. После ответа сохрани вариант, основания, отказы и последствия через `record --kind decision`
5. Каждому обязательству назначь владельца, срок, показатель и условие пересмотра
6. Согласуй, когда вернуться к решению
7. Заверши `check` и `checkpoint --stage followup`

Решение хранит `owner`, `due`, `metric`, `trigger`, `refs`, `option`, `approval`
Для реального `approved` нужно `approved_by` и ссылка на обезличенную запись согласования
Учебное решение имеет `approval: example` и не означает разрешения действовать
Если выбран статус-кво, всё равно зафиксируй дату и условие пересмотра
Не стирай старую запись, при замене создай новую с `supersedes`

Выход: читаемая запись решения и повестка через `work.py review`
